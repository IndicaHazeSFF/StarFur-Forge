# 2026-10-23 annotation-job storage sprint

## Scope

Checkpoint: WSL commit `972a705`. The initial unconnected, provider-free
private source/metadata store is followed by the result/checkpoint slice below.
Workers, API/CLI controls, durable user authentication and automatic cleanup
scheduling remain later slices. Existing ephemeral reviews are unchanged.

Use a separately supplied, host-owned private directory. Initial persistence
backend is POSIX/WSL only: native Windows denies until private-directory ACL and
handle-relative path controls have their own implementation/platform gate.
No production storage is created and no application constructs this store yet.

## Security and lifecycle

- Fixed expiry: 24 hours from original submission; no access/resume renewal.
- One OS-held lifetime owner lock; another live owner cannot recover its work.
- Restart fences queued/running metadata as interrupted without provider use.
- Explicit resume produces queued intent only; it is not execution admission.
- Expired content is unavailable even before explicit cleanup.
- Explicit delete/cleanup remove only validated job-owned records; no broad
  directory deletion or canonical-memory/adventure mutation.
- Private records are plaintext host storage, not encrypted/tamper-proof backup
  protection. Logical deletion cannot promise secure media erasure.
- Deny unsupported schemas, malformed content, path/link tricks and capacity
  overflow. No worker, HTTP/API authority, model-selected paths, or live network.

## Ten disposable WSL smoke gates

1. Submit/reopen private source and passive metadata separately.
2. Refuse a second simultaneous owner; accept one after release.
3. Recover queued intent as interrupted, never automatically queued again.
4. Recover running intent as interrupted; reject stale launch epoch.
5. Explicitly resume without changing original expiry.
6. Deny source access exactly at expiry before cleanup.
7. Cleanup only expired job-owned records, preserving unrelated files.
8. Explicitly delete a nonrunning job; deny deletion of running intent.
9. Refuse corrupted/unsupported durable records without rewriting them.
10. Refuse link/path/capacity violations without altering unrelated state.

Status: source/metadata foundation implemented; all ten disposable WSL gates
passed, including independent-process owner denial and corrupted-source refusal
before recovery writes. Native Windows passed the explicit unsupported-host
check (ten POSIX cases skipped). The final provider-free WSL suite ran 1,199
tests successfully (one native-Windows-only check skipped) with ResourceWarning
promoted to an error. All ten storage gates passed again after final source
fingerprint validation was moved ahead of recovery rewrites.
No production storage was created or configured. These are storage lifecycle smokes,
not live annotation quality, worker cancellation, Windows support, or verified
provider-stop evidence. Stop after these ten successful gates as requested.

## Deliberate deferrals / next slice

Validated result persistence and chunk checkpoints are covered by the follow-up
below; review rehydration and a trusted explicit submission/resume/deletion
surface remain deferred. A worker must separately honor provider
capacity, Focus Mode, stale completion fencing, interruption, and bounded retry.
Native Windows requires its own private-root ACL/handle validation. Abandoned
pending replacement recovery needs an explicit policy; current startup refuses
such files without guessing, replaying, or deleting them. Periodic cleanup and
physical-erasure/backup limitations remain product integration concerns.

## Result/checkpoint follow-up — ten new lifecycle gates

The user authorized another run until an issue or ten required smoke gates.
Implement a pure validated result codec and internal durable result/checkpoint
operations. Do not connect a worker or public control. Reuse the original fixed
expiry, private root, atomic replacement, and owner/attempt fences.

1. Completed result survives restart; passive metadata excludes its content.
2. Stale or expired completion cannot publish or replace current state.
3. Foreign source/chunk/observation/provenance refuses persistence.
4. Corrupted saved result refuses recovery without rewriting it.
5. Results obey fixed expiry and exact deletion alongside the source.
6. Explicit restart/resume preserves completed chunks outside the pending plan.
7. Valid empty and failed chunk outcomes remain distinguishable.
8. Identical checkpoint retry is idempotent; conflict/stale-attempt writes deny.
9. Incomplete/conflicting finalization refuses publication; complete assembly
   preserves original chunk order and provenance.
10. Injected atomic result-replacement failure preserves the prior record and
    does not restore a result during restart recovery.

during validation. The final provider-free WSL suite ran 1,215 tests

gates are provider-free and use disposable private stores, not real documents,
