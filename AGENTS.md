## Authority and stop rules

- Focused provider-free regressions and scoped `starfur.py assistant` terminal smokes are allowed on disposable/test-owned state; live model calls are limited to those smokes. Visual/audio/gaming acceptance needs Roger. Local debugging and fixes are allowed for understood ordinary failures; do not bypass safety gates or convert failed evidence into a pass.
- No implicit distro/service/config changes, installs, migrations, production repair, private processing or native test. Leave WSL lifecycle alone while Roger is active; dated lifecycle approvals are not standing permission. Read-only in-scope inspection is allowed. A non-loopback server listener alone is not proof of a client locality violation; inspect its actual role before proposing changes.
- Pause immediately on copy/hash/containment/permission failure, unexpected independent edits/effects, potential runtime-data impact or uncertain security behavior. Keep the queue; no forcing, retries, or workarounds. Escalate material design/authority decisions, missing credentials and unexplained repeat failures. Don't silently switch models or delegate; use Roger's chosen model (standing default Sol 6.1 High), and ask for higher reasoning when necessary.
- Check quota between slices and before substantial work. Follow the latest applicable Roger cutoff, otherwise reserve about 5% in each relevant window for verification and handoff. Unknown quota is not unlimited. If told to stop after a slice, finish safe verification/sync and hand off; after interruption inspect actual state, never assume completion.

## Exact sync, tests and backup

- Work in Windows first. Sync **only** the exact queued edited files to the above WSL repo. Record destination baselines; verify containment, no links/path escape, regular file targets, and pre/post hashes. Independent WSL drift is a stop; ordinary Windows/WSL differences before an authorized copy are expected. Never mirror, delete-sync, reset, or infer the queue from the dirty tree.
- Exclude `data/`, `adventures/`, Chroma, credentials, local config and unrelated files. Treat `data/starfur.db`, `data/sync_manifest.json` and `data/perf.jsonl` as runtime state. No reset/reinit/deletion as a shortcut; inspect, back up and get separate repair approval. Ordinary cleanup is limited to test-owned temporary state.
- Verify copies before testing. Remove only successfully verified paths from the queue and sync its final state; keep failed/unverified paths. A verified copy is not a test pass, commit or push. Corrective or subsequent edits re-enter the queue. Windows is the active source; recovery precedence is last verified GitHub commit, then Windows, then WSL. The Windows index may be stale.
- Run the relevant required suite; prefer temporary SQLite and fake Chroma/providers, never live Ollama/Chroma in unit tests. Keep package-qualified test imports, assert resource closure, and use the full discovery gate when required. Never make production initialization, analysis or ingestion a test side effect.
- Every ten successful **required runs**, back up the exact verified allowlist if authorized: one focused/subsystem/full run or mandatory smoke gate counts once, not its methods, optional runs or duplicate reruns. Use a furry subject and technical commit body. Keep exact paths in [development.unbacked.md](development.unbacked.md); exclude unrelated edits. Current GitHub hold and commit exceptions are in the handoff. Never treat cadence as authority to override a hold.

## Core contracts and handoff

- Core owns permissions, explicit commands, canonical memory/events, policy, validation and persistence. Providers, persona packages, latent state and diagnostic/proposal output are not authority. Keep assistant memory, project lore and adventure scopes separate; roleplay/adventure cannot silently rewrite real memory. Do not expose hidden reasoning or unrestricted private content. Ambiguous multiline Core control fails closed before commands, retrieval or generation; read-only diagnostics come from Core.
- Preserve canonical relative POSIX sources and provenance, human-authored canon outside managed spans, and existing data formats. Use the canonical source helper; review chunk/index version bumps for semantic changes. Reindex/cleanup can be destructive or non-transactional: don't run implicitly. Failed/partial annotation is not successful; do not mark its manifest clean. Review detailed subsystem contracts with the affected source.
- Each slice: maintain the operative roadmap milestone (complete only after required verification), concise changelog, and durable sprint evidence (exact paths/hashes, tests, sync/commit/push). Update this file for standing rule/authority or ownership changes, not routine outcomes; keep current implementation details in subsystem docs.
- Keep [next.steps.md](next.steps.md) small: live blockers/approvals/failed checks, next action, verification and backup status, plus the **last five completed slices**. Rotate only the recap as slices finish. Never age out unfinished, failed, unbacked or unresolved authority state. Reset the backup cycle/counter only after exact commit and verified push; carry unresolved work forward. Do not create recursive receipt-only commits.
- Maintain [user.smokes.md](user.smokes.md) until Roger revokes it. Keep manual/live requirements, prerequisites, checkpoint and result; prefer a test-owned helper. Development tests never imply operator acceptance, and pending checks survive recap or backup rotation.
