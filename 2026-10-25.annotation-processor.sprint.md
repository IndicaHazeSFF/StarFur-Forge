# 2026-10-25 bounded annotation processor sprint

Checkpoint: WSL commit `01aaa21`. Prior full suite: 1,223 tests, OK with one
platform-specific skip. User authorized up to twenty mandatory smoke gates,
then pause (earlier on operational failure or a material operator decision).

## Scope

Build an internal explicit one-chunk-at-a-time processor over the disconnected
private job store and existing application annotation boundary. No background
thread/service, public commands/API, durable user authentication, production
directory, review rehydration, automatic resume/retry, or live provider smoke.
All execution evidence here uses injected fake providers and disposable state.

## Ordered gate groups

### A — Exact application chunk boundary (five gates)

1. Select exactly one original chunk and retain source/provenance/options.
2. Recheck Focus Mode between explicit chunk requests, before provider use.
3. Refuse busy capacity before provider use; recover after lease release.
4. Refuse unavailable provider without probe, provider call or state write.
5. Refuse missing/duplicate/mismatched chunk bindings before provider use.

### B — Explicit processor/checkpoint loop (five gates)

6. Explicit start calls no provider; one step saves exactly one chunk.
7. Explicit resume selects only unfinished chunks after restart.
8. Valid empty extraction saves a checkpoint without inventing quality.
9. Bounded malformed extraction yields a failed chunk, not fabricated output.
10. Typed policy/capacity deferral retains work without retries or checkpoints.

### C — Interruption/concurrency fencing (five gates)

11. Ctrl+C fences the current attempt and preserves prior checkpoints.
12. Interruption during a fake call discards its late completion.
13. Concurrent step on one run refuses duplicate provider use.
14. Replaced run/attempt rejects stale output without changing fresh state.
15. Expiry during a fake call cannot publish/checkpoint late output.

### D — Completion/failure integration (five gates)

16. Explicit finish requires all chunk outcomes and makes no provider call.
17. Bounded provider-request failure releases capacity and saves its explicit
    failed chunk; a truly escaped runtime failure fences the run and preserves
    earlier saved work.
18. Malformed/foreign chunk result refuses checkpointing and fences the run.
19. Saved chunk/final result failure fails closed without automatic retry.
20. Full application/store flow: Focus Mode, capacity, steps, explicit finish,
    reopen completed result, no memory/proposal/adventure writes.

Status: all twenty unique integration gates passed in WSL (five in each group).
Group A also passed natively; 28 task-profile regressions and two pure processor
contract tests passed natively. The final provider-free WSL suite ran 1,245
tests successfully (one native-Windows-only skip) with ResourceWarning promoted
to an error. One group-D fixture initially expected an escaped request exception;
the adapter's existing bounded failed-chunk behavior was confirmed and that
expectation corrected, with a separate escaped runtime fault also checked.
No retry behavior was loosened or provider failure hidden as extraction success.
Repeated regressions/contract checks received no extra smoke-gate credit.
Paused after twenty successful unique gates as requested.
Group results are integration gates, not live
quality, latency, game cooperation, OS isolation or verified provider-stop proof.
Pure/unit regressions do not count as extra smoke credit. Disconnected run
handles and job IDs are internal state bindings, never user authentication.

## Next dependency / deliberate deferrals

Choose/implement a trusted explicit control and ownership boundary before any
public job submission, listing, resume, deletion or review rehydration. A local
CLI-first opt-in controller can avoid pretending conversation IDs authenticate
private stored documents; a shared API needs a real principal/access policy.
No choice was silently made or public endpoint added in this sprint.

Background scheduling/service startup/shutdown, provider-route/config binding
for durable work, retention sweep scheduling, review deletion/revocation links,
pending-replacement recovery, aggregate whole-job execution metrics, native
Windows storage and live annotation quality/performance remain separately gated.
The internal processor does not raise intake/file/output limits or establish
verified remote cancellation, OS isolation, or game-resource cooperation.
