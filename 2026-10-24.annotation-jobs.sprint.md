# 2026-10-24 annotation-job progress sprint

## Scope

The user authorized work until five mandatory smoke-test gates, then pause.
Build the bounded provider-free progress/read model needed before job controls
and a worker can report state. Do not connect an API, worker, provider, resident
dashboard, review rehydration, user authentication, or production directory.
Earlier source/result/checkpoint evidence remains in the 2026-10-23 record.

## Invariants

- Snapshot only job identity, original timestamps, closed state, result
  availability and bounded counts; never source names/text, domain, candidate
  wording, provenance refs, paths, prompts, or provider data.
- Checkpointed means saved chunk evidence. Full-run results without checkpoints
  must not invent checkpoint counts. Completed never implies factual quality.
- Listing/inspection never schedules, resumes, renews expiry, or rewrites state.
- The trusted private-store listing is not user authentication/access control;
  future public controls need a separate ownership boundary.
- Expired progress is unavailable even before cleanup; recheck at snapshot exit.
- All checkpoint candidate counts must fit the final-result ceiling before a
  checkpoint is saved, avoiding a permanently unassemblable aggregate.

## Five disposable WSL integration smoke gates

1. Queued progress/listing expose bounded content-free values without writes.
2. Checkpoint progress distinguishes saved candidates, failed extraction, empty
   extraction, and explicit result finalization.
3. Restart preserves actual counts, fences unfinished work, and never resumes
   or rewrites records just because a view was read.
4. Exact expiry hides progress/list entries without cleanup or deadline renewal,
   including expiry while a snapshot is assembled.
5. Aggregate overflow refuses checkpoint persistence; malformed stored state
   refuses the entire listing without publishing partial views or repairing data.
